SYSTEM ARCHITECTURE

Correctness by construction,
not by convention.

G1 — Double-Entry Invariant

Every settlement creates exactly two journal entries — one debit, one credit — of equal magnitude. The reconciliation engine continuously verifies the global journal sum equals zero.

// Every payment creates paired entries Dr DEBTOR_ACC -1,000.00 USD Cr CREDITOR_ACC +1,000.00 USD // ΣAllEntries ≡ 0.00 ✓
G2 — Idempotency via E2E_ID

Every payment carries a mandatory End-to-End ID. The engine enforces strict deduplication — submitting the same transaction twice produces exactly one settlement, never two.

POST /payments e2eId: "TXN-2024-XK7291" // Same ID submitted again → status: 409 DUPLICATE_BLOCKED
G3 — Append-Only Journal

Journal entries are written once and never modified or deleted. Corrections are made through compensating transactions. The historical state is always reconstructible from the immutable log.

// Write path: one direction only entry.write() → fsync() → ack // No UPDATE ever issued // No DELETE ever issued // Compensate, never mutate
G4 — ISO 20022 Native

Accepts raw PAIN.001 XML payment initiation messages directly. The engine parses, validates, and settles ISO 20022 formatted instructions without transformation middleware.

<CdtTrfTxInf> <PmtId> <EndToEndId>TXN-01</EndToEndId> </PmtId> <Amt><InstdAmt Ccy="USD">1000</InstdAmt></Amt> </CdtTrfTxInf>

SYSTEM GUARANTEES

Four properties. No exceptions.

G1 — IMMUTABILITY
Write Once,
Read Forever

Journal entries are append-only. No record is ever modified or deleted. Historical state is always reconstructible from the log alone.

G2 — IDEMPOTENCY
Safe
to Retry

Any payment with the same End-to-End ID submitted multiple times settles exactly once. Network retries cannot cause double-charges.

G3 — DOUBLE-ENTRY
ΣEntries
= 0.00

Every debit has a corresponding credit of equal value. Funds cannot appear or disappear. The reconciliation engine verifies this continuously.

G4 — DURABILITY
fsync

No acknowledgement is returned until the entry is flushed to disk. The system absorbs latency to guarantee zero data loss on crash or power failure.
